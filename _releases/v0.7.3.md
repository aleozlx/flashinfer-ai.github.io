FlashInfer v0.7.3 ships a slimmer `flashinfer-python` wheel on PyPI without experimental kernel sources (see Packaging below for the source install), brings MTP and NVFP4 MLA decode to Rubin, and speeds up expert-parallel MoE decode steps on Blackwell while Hopper gains MXFP4 and NVFP4 experts. Hybrid Gated DeltaNet models gain paged recurrent state for prefix caching, DeepSeek Sparse Attention models get token-sparse decode, `MoELayer` adds a low-latency small-batch path from Ampere to Blackwell, and a first set of training kernels covers GLM-5.3-Flash and Qwen hybrid models.

### DeepSeek-class MTP decode, Qwen3.5 deterministic MoE and Mamba2 prefill run on Rubin

`BatchMLAPagedAttentionWrapper` adds a `cute-dsl-rubin-mtp` backend for FP8 absorbed-MLA multi-token-prediction decode on SM107, and an experimental Cake backend decodes dense MLA from an NVFP4 paged latent cache in the Kimi K3 and DeepSeek-V3 geometry. The deterministic unfused finalize of the CuTe DSL fused MoE works on Rubin, which SGLang needs for Qwen3.5 NVFP4 on Vera Rubin NVL72, and `knobs="auto"` tunes Rubin MegaMoE through `autotune_v2()`. Rubin also gets an SM107-native blockwise FP8 GEMM behind `gemm_fp8_nt_groupwise(backend="auto")`, Mamba2 prefill through `SSDCombined(backend="cake")`, and Cake programs for DeepSeek routing, BGMV LoRA MoE, GDN and packed KDA decode.

### Expert-parallel MoE decode steps run faster on Blackwell, and Hopper adds MXFP4 and NVFP4 experts

`NVLinkOneSidedAlltoAll` adds a Lamport transport for decode-sized steps on B200, B300, GB200 and GB300 (`NVLinkOneSidedConfig(lamport=...)`), which lowers dispatch and combine time for DeepSeek-V3, Kimi K3 and Qwen3 MoE decode steps, measured end to end on Kimi K3 in vLLM; the backend now shares its kernels with TensorRT-LLM and scales to 256 ranks. Blackwell MegaMoE adds an opt-in GenPhase decode pipeline, and `knobs="auto"` tunes the Blackwell backends through `autotune_v2()`. On Hopper, `MoEEpLayer` runs FP8-activation experts with MXFP4 or NVFP4 weights, and the new `flashinfer.megamoe` package adds fused NVFP4 and MXFP4 expert-parallel MoE on H100 and H200 for DeepSeek-V4-Flash-class models, which SGLang uses for `DeepSeek-V4-Flash-NVFP4`.

### `MoELayer` adds a low-latency small-batch path from Ampere to Blackwell and MXFP8 experts for Nemotron 3.5 Super

`FrostLowLatencyConfig` selects an opt-in cuDNN Frost backend of the unified `MoELayer` for routed MoE at one to eight tokens, covering BF16, FP16, FP8 (per-tensor and DeepSeek block), MXFP8 and NVFP4 experts and weight-only NVFP4, MXFP4, MXINT4 and E4M3 formats on SM80 (BF16 and FP16 only), SM90, SM100, SM103, SM107 and SM120. cuDNN grouped-GEMM backends (`CudnnGroupedGemm*Config`) join the same API as a further opt-in, and the cuDNN Frost grouped-GEMM backend covers BF16, MXFP8, NVFP4 and MXFP8-activation/MXFP4-weight experts on SM120, where auto-selection admits it. The CuTe DSL fused MoE adds MXFP8 activations with MXFP8 weights for Nemotron 3.5 Super's non-gated ReLU² experts on B200 and B300, raising vLLM throughput at high concurrency over BF16 experts.

### Hybrid Gated DeltaNet models serve with prefix caching, and Gated DeltaProduct gets decode and prefill kernels

`flashinfer.gdn_paged` keeps Gated DeltaNet recurrent state in a paged pool with a CSR page table, so a serving engine's prefix cache can share and resume GDN state like paged KV: `chunk_gated_delta_rule_paged` writes a state at every page boundary and never touches prefix pages, `gated_delta_rule_decode_paged` updates pages per token, and `gdn_prefix_materialize` reconstructs a state at a fixed boundary from the decode checkpoint ring. GDN prefill also runs on Ampere. Gated DeltaProduct, the multi-step DeltaNet recurrence, gets `cake_gated_delta_product_mtp` for decode and MTP decode on H100, B200 and B300 and a `backend="cake"` chunked varlen prefill on H100. `fused_kda_decode` covers GLM-5.3-Flash's 64 Kimi Delta Attention heads at TP1 to TP4 and vLLM's dimension-first conv-state layout for disaggregated serving.

### Token-sparse decode serves DeepSeek Sparse Attention models, and sparse MLA reads NVFP4 and FP8 caches

`trtllm_batch_decode_with_kv_cache(sparse_top_k=K)` runs token-sparse MQA decode on the trtllm-gen kernels, where each query token, MTP drafts included, attends only the keys its indexer selected; `token_sparse_kv_indices` builds the per-token page tables and `group_union_masks` lowers the same selection onto dense kernels. The experimental Prims-TS sparse-MLA decode wrapper serves DeepSeek Sparse Attention (DSA) decode for GLM-5.3 and DeepSeek-V3.2 from an E4M3 latent cache on B200 and B300, and adds NVFP4 and per-tensor FP8 cache recipes. Query sparse attention (QSA) gets cuDNN-backed `qsa_forward` and `qsa_indexed_forward` on B200, B300 and Rubin and an experimental `qsa_sparse_paged_attention` over NVFP4 paged caches on A100 and H100, and MiniMax-M3's `msa_*` sparse attention ops now run on H100.

### Sliding-window context attention reaches Blackwell and Rubin, and GLM-4.7 runs FP8 prefill on RTX PRO 6000

The TRTLLM-Gen context kernels accept a fixed sliding window and per-token `VariableWindow` bounds on B200, B300 and Rubin. `backend="auto"` routes more Blackwell shapes to cuDNN: single-token head-dim-256 paged decode in its measured CTA band, and causal BF16 paged prefill on B200 for both prefix-extension and full-sequence requests (cuDNN frontend 1.32 and cuDNN 9.27 or newer). FA2 takes a per-token, per-head FP8 KV scale for vLLM's dynamic `fp8_per_token_head` cache. On RTX PRO 6000, GLM-4.7 and GLM-4.7-Flash get FP8 prefill attention, and SM120 sparse MLA reads DeepSeek-V4.1 inline-scale KV records natively (`kv_cache_format="fp8_dsv41_inline"`).

### Packaging: the PyPI wheel no longer bundles experimental kernel sources

Starting with v0.7.3, the `flashinfer-python` wheel on PyPI leaves out the generated CUDA kernel sources of the packages under `flashinfer.experimental`: each package's `csrc/` directory and the shared `csrc/experimental/` tree. This keeps the wheel under PyPI's 100 MiB per-file limit: the full build is 106 MB, the published wheel 80 MB. Everything else is unchanged: every stable API and its JIT sources are in the wheel, and `flashinfer-cubin` and `flashinfer-jit-cache` are unaffected.
{: .release-wrap }

**What you will notice.** `import flashinfer` and the experimental Python modules work as before. Calling an experimental API from a PyPI install fails the first time it builds its kernel, with a JIT build error naming a missing `.cu` file under `site-packages/flashinfer/experimental/<package>/csrc/`; the few experimental APIs that have a composable PyTorch fallback log a warning and use it instead. `flashinfer/experimental/KERNEL_SOURCES_EXCLUDED.txt` inside the installed package records why. Affected packages include the Cake experimental backends such as `cake_kda_train`, `cake_gdn_det_train`, `cake_mok_bf16`, `cake_stepfun_moe`, `cake_nvfp4_per_token` and `cake_dsa_indexer`, the DeepGEMM-derived backends, the Kimi K3 and MiniMax-H3 packages, the NVFP4 attention and MLA decode packages, `msa_nvfp4_decode`, `sm110_gqa_decode` and `sm110_xqa`. `b12x` is not affected.
{: .release-wrap }

**To use experimental APIs, install from source.** Either command builds the full package locally in a minute or two; no CUDA toolkit is needed at install time, since kernels still compile on first use:

```bash
pip install --no-binary flashinfer-python flashinfer-python==0.7.3
```

```bash
pip install git+https://github.com/flashinfer-ai/flashinfer.git@v0.7.3
```

Experimental APIs remain opt-in with no compatibility guarantee, as described in `flashinfer/experimental/README.md`.

> **⚠️ Upgrade notices**
>
> - Install `nvidia-cudnn-frontend>=1.32.0` and `nvidia-cutlass-dsl>=4.8.0`: `pip install -U 'nvidia-cudnn-frontend>=1.32.0' 'nvidia-cutlass-dsl>=4.8.0'`. Environments pinned to an older CuTe DSL must upgrade.
> - After upgrading `flashinfer-python`, run `flashinfer download-kernels` to replace mismatched `flashinfer-cubin` and `flashinfer-jit-cache` wheels; FlashInfer ignores wheels from another version and falls back to JIT compilation and on-demand cubin downloads.
> - Expert-parallel MoE: `flashinfer.comm.MoeAlltoAll`, `MnnvlMoe` and the `flashinfer.comm.moe_a2a_*` functions are removed together with the `backend="trtllm"` all-to-all kernels; use the `flashinfer.moe_ep` communication backends (`NVLinkOneSidedAlltoAll`, `CakeAlltoAll`, `NVLinkTwoSidedAlltoAll`, or `SplitConfig(comm=...)`), and rename `dispatch(max_tokens_per_rank=...)` to `runtime_max_tokens_per_rank=...`.
> - `UlyssesCommunicator(max_elems=...)` is deprecated in favour of `max_bytes=max_elems * dtype.itemsize`; the old keyword still works and emits a `DeprecationWarning`.

### Known issues

- cuDNN ragged prefill (`BatchPrefillWithRaggedKVCacheWrapper(backend="cudnn")`) is slightly slower on GB300 than in v0.7.2.post1 for GPT-OSS-shaped long prefill (batch 16, 8K query and KV tokens, 64 query and 8 KV heads, head dim 64). The regression is under investigation.
- On RTX PRO 6000, `cudnn_batch_prefill_with_kv_cache` returns wrong values when `actual_seq_lens_q` or `actual_seq_lens_kv` is shorter than the storage span given by `batch_offsets_q` and `batch_offsets_k`, that is, when Q or KV carry storage padding ([#7687](https://github.com/flashinfer-ai/flashinfer/issues/7687)). Pass unpadded inputs on SM120.
